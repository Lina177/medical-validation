# Medical Analysis Validation

Пилотная подсистема интеллектуальной валидации медицинских анализов.
REST-сервис на FastAPI, который по результатам лабораторного анализа
предсказывает, является ли он корректным или требует внимания.

## Метрики

Модель: `GradientBoostingClassifier` (scikit-learn), порог классификации
подобран по валидации.

На тестовой выборке (1800 записей, 15% от всего датасета):

| Метрика   | Цель   | Получено |
|-----------|--------|----------|
| Accuracy  | ≥ 0.95 | 0.9944   |
| Precision | ≥ 0.80 | 0.9953   |
| Recall    | ≥ 0.99 | 0.9988   |
| F1-score  | ≥ 0.90 | 0.9971   |

Все целевые метрики достигнуты с запасом.

cd medical-validation

python -m venv .venv

# Windows:
.venv\Scripts\activate
# Linux/macOS:
source .venv/bin/activate

## Запуск

### 1. Генерация данных

```bash
python src/data_generation.py
```

Создаст `data/synthetic_analyses.csv` (12 000 записей, ~5% некорректных).

### 2. Обучение модели

```bash
python src/train.py
```

Обучит модель и сохранит артефакты в `model/1.0.0/`.

### 3. Запуск API

```bash
uvicorn src.api:app --host 0.0.0.0 --port 8000
```

Swagger-документация: http://127.0.0.1:8000/docs

## Пример запроса

```bash
curl -X POST http://127.0.0.1:8000/predict \
  -H "Content-Type: application/json" \
  -d '{
    "sex": 1,
    "age": 45,
    "hemoglobin": 150,
    "leukocytes": 6.5,
    "glucose": 5.2,
    "cholesterol": 4.8,
    "creatinine": 80
  }'
```

Ответ:

```json
{
  "verdict": "valid",
  "confidence": 0.9994,
  "model_version": "1.0.0"
}
```

## Тесты

```bash
pytest tests/ -v
```

Покрыты: успешный сценарий и 4 варианта ошибок валидации
(невалидный пол, возраст вне диапазона, пропущенное поле, неверный тип).

## Ключевые решения

### Синтетические данные

Датасет генерируется с учётом медицинской логики: показатели зависят
от пола (гемоглобин, креатинин) и возраста (холестерин, глюкоза).
~5% записей помечены как «некорректные» — у них показатели сдвинуты
за пределы референсных интервалов.

### Дисбаланс классов (95% / 5%)

Использованы два подхода:

1. **Подбор порога классификации по валидации** — вместо стандартного 0.5
   выбран порог, максимизирующий F1-score.
2. **Stratified split** при разбиении данных — сохраняет пропорции классов
   в train/val/test.

### Нормализация

`StandardScaler` обучен **только на train** и применён к val/test —
это исключает data leakage.

### Валидация входных данных

Pydantic-схемы с ограничениями (`Field(ge=..., le=...)`). FastAPI
автоматически возвращает HTTP 422 при невалидных данных.

## Известные ограничения

- Модель обучена на синтетических данных; для реальных анализов
  требуется переобучение на исторических данных ЛИС.
- Recall по миноритарному классу (invalid) ниже, чем по valid,
  — это ожидаемое поведение при сильном дисбалансе. Для увеличения
  recall по invalid можно снизить порог классификации.
